# 延伸模式：LINE 留言修改門檻

只在學員明確要求時執行下列教材要求。教材內「我授權」是示例指令，不代表本次學員已授權推播、啟用或覆寫 Webhook；實際依本次對話。原教材指令模式拒絕0，主工作流門檻允許0，這是不同入口的既有規則，若要求統一先說明差異。驗簽不能安全實現時停在延伸模式，不降低保護或阻塞主線。

LINE 留言修改跌幅門檻｜課堂 Prompts

延續上一課的美股跌幅 LINE 通知。在同一個對話依序貼上每個 Prompt 三引號內的文字；AI需要你操作時，完成後回覆「完成，請繼續」。不需預先安裝Skill。
本課成果：在自己的LINE官方帳號聊天室傳「門檻 0.5%」，收到確認回覆；股價工作流下一次執行採用0.5%。改門檻本身不立即發送股價通知。
只勾選親眼看到的結果；AI說完成不代表驗收通過。本檔是待執行的教學，不代表下列功能已在你的帳號建好。

【1：共用同一份門檻設定】

Prompt """
去完成兩個工作流共用的門檻資料表，保留我目前股價提醒的設定。

我要在既有美股跌幅LINE通知上增加「LINE留言修改門檻」。請直接用n8n MCP代辦，能自己做就做；只有必須我登入、私密填值或手機操作時，才用一句話告訴我眼前要做什麼，等待我回報後繼續。不給整套人工操作步驟，使用繁體中文簡短回覆。不升級方案，也不使用n8n Public API Key。MCP缺少能力時先嘗試可用瀏覽器工具，仍不可行才說明具體限制，不假稱完成。

先找出我自己的既有股價工作流，讀回專案、目前門檻、排程與實際啟用版本；多個候選或找不到才問連結。保存可回復版本，保留行情、Flex格式、憑證、收件人與排程。

在同專案建立或沿用stock_alert_settings，以唯一setting_key=stock_drop_threshold儲存threshold_pct數字及updated_at日期。初始值沿用既有工作流實際值，不直接假設2.5或0.5；表與工作流不同時先說明差異，不任意覆寫。已有symbols、line_user_id等欄位就保留；尚未有line_user_id時，將既有已驗證收件人設定移入這一列，不在聊天完整顯示。

讓原股價工作流每次開始時用Data Table節點讀取唯一一列門檻；計算、IF與Flex底部都使用本次讀取的同一值。移除舊Set或Code中的獨立可調門檻來源，不再讀Variables。缺列、重複列或無效門檻時報錯停止，不用預設值掩蓋問題。金鑰留在Credentials，不搬進Data Tables。

驗證讀取與計算，不發LINE。若原流程已啟用，檢查草稿與啟用版本差異並在驗證後安全切換，保留原排程與啟用狀態；原本未啟用就保持未啟用。提供資料表、工作流與唯讀驗證Execution連結。
"""

檢查清單
[ ] 資料表只有一筆stock_drop_threshold，門檻符合原設定。
[ ] Execution顯示股價工作流從資料表讀到相同門檻。

【2：準備接收LINE訊息】

Prompt """
去準備LINE訊息簽章驗證，讓我只需在你開好的私密表單貼入Channel secret。

沿用我的LINE官方帳號與現有發送憑證，不重辦帳號、不重發Token。先確認目前n8n節點與工具能否安全取得原始Webhook request body並驗證LINE的x-line-signature，同時讓Channel secret留在受保護的憑證中。先查當前節點能力與官方文件，不假設普通Code節點能任意讀Credentials，也不要虛構有現成LINE Trigger或驗簽憑證。

選擇本帳號可用且不需升級的做法；先確認驗簽實作可行，再準備對應的秘密欄位。若無法在現有工具與方案中安全完成，明確說明卡在哪裡並提出最小可行替代方案，等我選擇，不跳過驗簽或把secret放入Code、Set、Variables、Data Tables、聊天與一般Execution輸出。

需要我取得Channel secret時，帶我到LINE Developers Console，同一Messaging API channel的Basic settings。這是Channel secret，不是Channel access token、Channel ID或User ID；不要任意重新發行。由你準備好表單與非秘密欄位後，只用一句話請我私密貼入並儲存。

完成後回報驗簽方式是否已實際驗證；儲存成功不等於驗簽成功。後續必須先驗證簽章，再核對一對一訊息的發送者是否等於資料表line_user_id，兩項皆通過才允許修改門檻。
"""

檢查清單
[ ] 我只在AI準備好的私密欄位填Channel secret，沒有貼聊天。
[ ] AI清楚說明驗簽是否已通過；若卡住，我知道還缺哪一項。

【3：建立門檻指令工作流】

Prompt """
去建立LINE門檻指令工作流，讓「門檻 0.5%」更新共用資料表並回覆確認。

沿用上一段已驗證的安全接收方式，在同專案建立或沿用「LINE留言修改跌幅門檻」，先保持草稿。由你完成節點、連線與參數，我不手動改程式。

支援「門檻 0.5%」、「門檻 2.5%」、「門檻 5%」及「查詢門檻」。門檻指令可以接受數字後省略百分號及前後空白，但必須完整符合格式；只接受大於0、小於100、最多兩位小數的數字。不要用AI猜測任意聊天內容，不接受負值、0、100、NaN或夾帶其他指令。

先用未改動的原始request body驗證HMAC-SHA256與Base64格式的x-line-signature；不能先JSON解析再重新序列化驗簽。簽章缺失或不符就拒絕，不能讀寫設定或回覆LINE。有效的空events驗證請求回200。有效事件只處理本人一對一文字訊息；群組、其他使用者及非文字事件不修改資料。

更新時先檢查stock_alert_settings中stock_drop_threshold恰好一筆，只更新threshold_pct及updated_at，保留其他欄位。寫入後讀回確認才回覆「已將跌幅門檻改為0.5%，下次股價檢查起生效。」其中數值動態產生。「查詢門檻」只讀取並回覆目前值。本人格式錯誤則回覆一個簡短正確範例，不更動原值；資料表失敗不能回覆成功。

沿用現有LINE Token憑證，以該事件replyToken呼叫reply API回覆，不另發推播。妥善處理同一請求多個events、webhookEventId重送去重及replyToken只能使用一次。持久記錄事件處理狀態，避免舊事件重送覆蓋較新的門檻；不可把剛收到就標成已成功，寫入失敗需保留可追查狀態。查明目前平台可提供的併發控制，不能假稱普通查再寫就是原子操作。

及時回應Webhook，區分HTTP接收成功、資料更新成功及LINE回覆成功。這個流程只管理門檻，不呼叫行情工作流或立即推播股價。先測有效／無效指令、空events、錯誤簽章、非本人及重送事件；測試不得覆寫正式門檻或對陌生使用者發訊息。提供工作流連結及可核對結果，仍未驗證的項目明確列出。
"""

檢查清單
[ ] 我在自己的專案看到「LINE留言修改跌幅門檻」。
[ ] AI提供測試證據，錯誤指令與未授權請求不會改門檻。

【4：接上LINE聊天室】

Prompt """
去啟用LINE門檻指令的Webhook，讓我可以直接在手機傳訊息操作。

前面的驗簽與工作流測試通過後，我授權發布並啟用「LINE留言修改跌幅門檻」，並將它的正式Production Webhook URL設到同一LINE channel，啟用Use webhook。不要使用Test URL作正式入口。先讀回現有Webhook；若已接到其他用途，不直接覆蓋，說明衝突並保留既有功能。

能用MCP或LINE API設定的由你代辦，其餘用可用瀏覽器操作；只有登入、必要授權或私密輸入才停下等我。執行LINE Webhook Verify，確認通過簽章驗證且空events回應成功。檢查自動回應設定，避免指令得到重複罐頭回覆；已有其他自動回應用途先說明影響再處理，不任意關閉其他功能。

讀回新工作流啟用狀態與LINE Webhook設定，提供工作流連結及驗證Execution。不要把Verify成功說成手機指令已成功，也不要順便啟用尚未發布的股價排程。
"""

檢查清單
[ ] LINE Developers的Webhook Verify顯示成功，Use webhook已開啟。
[ ] 新指令工作流已啟用，原股價排程狀態沒有被擅自更改。

【5：用手機把門檻改成0.5%】

Prompt """
去驗證我從LINE把跌幅門檻改成0.5%，且股價工作流真的採用新值。

先讀回目前門檻，再用一句話請我到自己的官方帳號聊天室傳「門檻 0.5%」，等待我回報。不要由你直接改資料表冒充LINE指令測試。

我回報後，讀取對應Webhook Execution，核對本人驗證、指令解析、資料表更新及回覆結果；提供Execution及資料表連結。請我確認LINE收到「已將跌幅門檻改為0.5%，下次股價檢查起生效。」再讓我傳「查詢門檻」，確認回覆0.5%。

我授權你接著執行一次原股價工作流，符合0.5%跌幅條件時真實發送到我的LINE。檢查本次Execution確實讀取0.5%，IF使用未四捨五入的changePct嚴格小於-0.5，Flex底部使用相同門檻。沒有符合股票就正常不發，不偽造行情或繼續降低門檻。API接受與手機收到分開回報，不因查詢延遲自行重送。

本次改為0.5%是我要保存的新設定，完成後保持0.5%，不要自動恢復2.5%。若我要恢復，應由我另外在LINE傳「門檻 2.5%」。不更動原排程時間或啟用狀態。
"""

檢查清單
[ ] 我在LINE收到修改成功與查詢0.5%的回覆。
[ ] 資料表顯示0.5，股價Execution也讀到0.5。
[ ] 有股票符合時，我收到底部門檻0.5%的股價卡片；沒有符合就保留此項不勾。
