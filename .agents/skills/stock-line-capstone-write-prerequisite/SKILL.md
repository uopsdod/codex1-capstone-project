# LINE 留言修改門檻：前置檢查

## 範圍

本系列讓本人在既有官方帳號聊天室傳「門檻 3%」修改通知門檻，傳「查詢門檻」查看目前值。只修改跌幅門檻，不包含聊天改股票、自然語言投資問答或立即推播行情。本次使用此 Skill 是前置檢查，不代表已授權正式遷移、發布或發送。

## 檢查與準備

1. 發現當前可呼叫的 n8n MCP，讀取本專案既有通知工作流、真正啟用版本、專案與憑證引用。多個候選有歧義才問。沿用有效連線，不重辦帳號或索取 Public API Key。MCP 缺少能力時具體回報，不以瀏覽器操作冒充 MCP 驗收。
2. 讀回目前門檻、股票、收件人、行情與卡片使用門檻的位置、排程及去重方式。區分現行設定節點與歷史 Data Tables，不假設門檻為 2.5%。盤點同專案是否已有共用設定表；值不一致時列差異，不任意覆蓋。
3. 查核現行 n8n 節點與官方文件：能否取得 Webhook 原始請求位元組、安全使用 Channel secret 驗證 HMAC-SHA256，以及保護秘密不進入一般參數或 Execution 輸出。不能假設普通 Code 節點能讀 Credentials 或安裝模組。先確認可行方案，再準備秘密表單；若需要額外服務、費用或新增存取權限，說明具體對象與範圍，等待選擇，不跳過驗簽。
4. 沿用 LINE 官方帳號與發送 Token 憑證。檢查既有 Webhook URL、Use webhook、自動回應用途與事件重送設定；已有入口時記錄整合需求，不直接覆蓋。驗簽後仍須核對一對一傳訊者等於已確認的本人收件帳號；不以顯示名稱或 Basic ID 判定本人。
5. 若缺 Channel secret，用 Codex 內建瀏覽器開啟同一 Channel 的 LINE Developers → Basic settings，說明取得位置。由 Codex 準備受保護的秘密欄位，請本人私密貼入並儲存；不要求貼聊天、不讀出金鑰、不任意重新發行。Channel secret 與 Channel access token 不同。登入或必要授權交接眼前一步，其餘由 Codex 接續。
6. 確認工具能建立、讀寫 Data Tables、精準修改與發布工作流、讀取 Execution，並盤點事件去重及併發／順序控制。驗簽或必要資料能力不可用時，指出具體阻礙與可行下一步；保留原本單向通知不動。

## 缺連線時的引導與接續

前置檢查包含協助補齊必要連線，不只列缺項就結束。先完成不受影響的唯讀檢查，再針對眼前阻礙交接一項具體操作，等待本人回報後接續原進度，不重跑已完成項目。

- **n8n MCP 尚未連線或未授權**：依實際工具錯誤引導連接目前實例。需要本人操作時，指出當前介面的連線／Authenticate／OAuth 必要一步；授權已成功但工具未載入時先嘗試支援的重新載入方式，只有確有需要才請完整退出並重開 Codex、回到原對話輸入「繼續」。不要反覆要求成功過的 OAuth，不動其他 MCP。
- **Codex 內建瀏覽器可用，但網站尚未登入**：代開目前 n8n 或對應 LINE Developers 頁面，請本人完成該網站登入，回覆「已登入，請繼續」。不要索取密碼、驗證碼或 Token；確認登入成功後直接繼續盤點與準備憑證。
- **內建瀏覽器工具／服務不可用**：區分工具連線錯誤與網站登入錯誤，查可用工具及正式故障排除方式；不可直接宣稱缺少帳號登入，也不可把重新登入網站當成工具服務的修復。若有已確認的啟用／重連步驟，提供眼前那一步並等待；若無可驗證修復方式，明說限制。可提供對應官方頁面讓本人先登入準備，但這不代表 Codex 已恢復操控能力。不要改控 Chrome 或要求安裝未經選擇的替代服務。
- **需本人私密輸入**：先由 Codex 準備好受保護的表單，再提供正確取得位置與欄位名稱。對本專案為 LINE Developers 同一 Channel → Basic settings → Channel secret，填入 n8n Crypto 憑證的 Hmac Secret。不得要求將秘密貼到聊天或把秘密存入一般欄位。若工具尚不可用，先恢復能力，不假稱表單已準備。

每次交接說清楚「在哪裡、做什麼、完成後回覆什麼」，保留本次檢查結果。本人回覆完成後，先實際確認連線／登入／憑證狀態，再繼續；本人回覆與工具實測分開記錄。缺少的安全驗簽與手機測試不預先標通過。

## 舊練習 Webhook 與跨實例檢查

比較 LINE 現有 Webhook 的主機與本次已確認 n8n 實例，不只檢查路徑。若不同，先確認舊入口用途；本人已明確表示為舊練習、此次要換到新實例，就記錄這項決定並接續，不反覆詢問同一問題。404 只證明該次入口驗證失敗，不據此推斷秘密錯誤或整個帳號失效。

前置檢查只記錄現有 URL、Use webhook 狀態及證據來源（MCP、本人截圖或本人回覆），不直接換主機名稱、不按 Verify 重試未建好的入口。新指令流程完成安全驗簽、取得正式 Production URL 並依上線指示啟用後，再由 main 切換 LINE 入口；保留原通知與排程。實例名稱、Channel、工作流與門檻都從當次證據取得，不把老師的網址寫成預設。

若 MCP 無法建立秘密憑證且內建瀏覽器控制尚不可用，說明這項具體限制後可交接最小必要的手動憑證步驟，不能因此要求提供秘密到聊天。先引導開啟本次 n8n 專案的 Credentials，依畫面建立 Crypto 憑證，名稱建議「LINE 訊息驗簽」，只將同一 Channel 的 Channel secret 填入 Hmac Secret 並儲存，其餘秘密欄位不需填。由本人回報後用 MCP 讀取憑證名稱與類型確認存在；若找不到 Crypto 類型，請回報畫面，不猜替代欄位。不要宣稱 Codex 已準備表單，也不把憑證存在當作驗簽實測通過。

## 交接

用「項目／✅ 通過、❌ 未通過、⏳ 待驗證／證據與下一步」表回報。交接實例、專案、原工作流及啟用版本、原門檻、設定來源、憑證名稱與用途、本人身分確認方式、Webhook 衝突、安全驗簽方案及是否實測、資料表與併發能力、未完成事項。不要輸出秘密、完整 User ID 或完整敏感請求。

確認可建置後，告知下一步使用「LINE 留言修改門檻建置 Skill」（$stock-line-capstone-write-main），不自動開始遷移。儲存秘密成功不等於驗簽通過。

## 瀏覽器控制服務未連接時

若瀏覽器控制回傳 `Trusted RPC service is not configured: browser` 或同等的服務未配置錯誤，不將它解釋成網站未登入。先保留目前進度與下一步，請使用者：「請完整退出 Codex（macOS 可按 Command + Q），再重新開啟，回到原對話輸入『繼續』；不需要建立新對話或重做已完成的 OAuth。」等待本人回報，不連續重試相同失敗呼叫，也不直接改走整套人工建置。

重新開啟後重新發現工具，建立當次瀏覽器連線，先列出分頁，再讀取本次目標頁面確認；必要的網站登入另行交接。這次實測重開後內建瀏覽器與 Chrome 均恢復連線，但不保證所有錯誤皆能如此修復。仍失敗就提供實際錯誤與已嘗試步驟，不反覆要求重開、重新授權 n8n MCP 或重新登入網站。Chrome 只在使用者明確選擇後使用；恢復後接續原憑證準備，不重複建立。
