# LINE 留言修改門檻：前置檢查

## 範圍與分工

本系列在既有股票通知上新增「門檻改成 2%」及「查詢門檻」。固定句型即可，不需模型猜測聊天；不包含留言改股票或立即推播行情。Codex 代辦技術設定，本人只完成登入、必要授權、私密輸入與手機確認。一次只交接眼前必要的一步，說明在哪裡、做什麼、完成後回覆什麼；回報後接續原進度。

本 Skill 只完成前置準備，不修改正式門檻、不發布指令入口、不發 LINE。保留已完成的證據，重複執行不重辦帳號、不重填既有金鑰。

## 檢查順序

1. 發現並呼叫 n8n MCP 的實例 context，取得本次專案、原通知工作流、真正啟用版本及非秘密憑證引用。多候選有歧義才問，不用老師的網址或 ID；缺 MCP 時協助連線，不以瀏覽器驗收冒充 MCP 通過。
2. 重新讀取實際股票、門檻、本人路由、設定來源、行情／IF／Flex 使用門檻的位置、排程及去重方式。區分設定節點、已遷移共用表與舊實驗表。已有表的值若不同，記錄差異與初始化依據，不自行覆寫；尚無共用表是 main 的建置工作，不算前置缺失。
3. 沿用原「LINE 股價提醒」等發送憑證及同一官方帳號。既有本人身分確認有效就沿用；未確認時核對實際接收通知的個人帳號，不以 Bot userId、Basic ID 或顯示名稱代替本人。
4. 檢查 LINE Webhook URL、Use webhook、redelivery 與自動回應的實際狀態。預設第一次設定：URL 空白正常，等新工作流建好才設定。只有發現既有 URL 才確認用途；本人已說是可替換的舊練習就保留決定，不反覆詢問。主機不同或404只記為入口問題，不直接換主機或反覆 Verify 未建好的入口。
5. 查本次節點與官方定義，確認原始 body、Crypto HMAC-SHA256/base64、受保護秘密、Data Tables 讀寫、工作流精準修改／發布及 Execution 讀取能力。Crypto v2 的 Hmac Secret 可保存在 crypto 憑證；不能假設 Code 能讀 Credentials。參照 main 的 [實作規格](../stock-line-capstone-write-main/references/implementation.md)，此階段確認可行方案，運行實測留給 main。
6. 缺驗簽憑證時，用內建瀏覽器在本次 n8n 專案準備 Crypto 表單，命名「LINE 訊息驗簽」。引導至同一 LINE Developers Channel → Basic settings → Channel secret，請本人私密複製至 Hmac Secret 並 Save，其餘秘密欄位留空。Channel access token 是原本發送／回覆用憑證，Channel secret 是新接收驗簽用途，不重新發行既有秘密。本人儲存後以 MCP 確認名稱、類型及可使用權限；存在不等於驗簽實測通過。

## 連線與登入交接

- **MCP 未連線／授權不足**：依本次錯誤引導實例設定、Authenticate 或 OAuth 必要一步；不索取 Public API Key、不動其他 MCP，不反覆做已成功的 OAuth。工具未載入先使用支援的重載方式，確有需要才請重開 Codex。
- **瀏覽器可控但網站未登入**：代開正確頁面，請本人登入並回覆「已登入，請繼續」。不索取密碼或驗證碼；完成後確認登入，再繼續。
- **瀏覽器回報 `Trusted RPC service is not configured: browser` 或同等錯誤**：保留進度，請本人完整退出 Codex（macOS 可按 Command + Q）、重新開啟、回原對話輸入「繼續」。重開後重新發現工具、列出分頁並讀取目標頁。這是實測有效的排除步驟，不保證所有錯誤可修復；仍失敗就回報實際限制，不反覆要求重開或把網站登入當工具修復。
- 預設內建瀏覽器；本人明確選擇後才改用 Chrome。兩者皆不可用且 MCP 無建立秘密憑證能力時，可交接最小手動表單步驟；不假稱表單已備好。找不到 Crypto 類型就先取得畫面與版本，不猜替代欄位。
- 不要求秘密貼聊天，不讀出、截圖或保存秘密到一般參數、程式、表格或分享檔。LINE設定頁可能直接顯示Token；只讀目標設定區塊，不輸出整頁內容或拍入秘密。需要新服務、費用或擴大存取權限時，先具體說明並取得當次必要指示，不默默升級方案。
