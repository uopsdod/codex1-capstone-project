# n8n 工作流建置與驗證

## 輸入與範圍

接收使用者或上層專案 Skill 的需求：目標、觸發、資料來源、輸出、條件、專案與既有工作流ID、驗收方式、允許的外部操作。沿用對話中已確認的設定與授權，不重複詢問。缺少會影響正確性的資訊才問；不要擅自加入通知、排程、付費服務或其他功能。

本 Skill 提供 n8n 技術實作，不決定業務規則。股票、門檻、LINE版型等由上層專案規格提供；遇到衝突以使用者指示為準並指出差異。調用本 Skill 是在同一對話讀取並遵循指引，不要求另開聊天或啟動子代理。

## 工具與環境

1. 發現本對話可呼叫的 n8n MCP 工具，先 get_instance_context。無曝光工作流不表示空白實例；搜尋專案與既有資源，避免重複建立。
2. MCP未載入、授權不足或連線失敗時，回報具體缺項，保留已完成設定。不用瀏覽器結果冒充MCP驗證。環境連線依課程TXT或使用者現有設定，不為單一工作流擅自改MCP配置。
3. 讀取既有工作流、草稿與啟用版本及非秘密憑證引用。修改前保留可回復的非秘密版本，避免覆寫未相關變更。專案／資料表／資料夾用工具查得的ID，不猜。

## 建置流程

遵守當前 n8n MCP 的建置要求，工具名稱與能力以實際發現為準：
1. 寫SDK前讀 get_workflow_sdk_reference；依需要讀 guidelines、design等章節。SDK描述靜態圖，不把工作流JSON當SDK，也不在builder裡使用未支援的任意JS。
2. 用 get_workflow_best_practices 取得本次相關技術模式。先 list 探索不確定項；選與任務相符的模式，不額外引入功能。
3. search_nodes，再 get_node_types 取得所有使用節點的版本及 resource／operation／mode。依型別配置，不猜參數。資源選單用 explore_node_resources 查得真實值；憑證使用既有ID及正確型別，不讀出秘密。
4. 優先使用適合的原生節點，必要邏輯才用Code。處理item數、資料傳遞、空集合、錯誤分支與副作用次數。重要業務值使用同次執行快照，不硬編碼第二來源。
5. 配置節點後 validate_node_config，再 validate_workflow，修正後才建立。依複雜度決定是否需要node groups，遵守SDK分組規則；簡單單一目標不必分組。
6. create_workflow_from_code附簡短description與versionName。修改既有節點使用參數更新，不刪除重建而破壞連線／子節點；update_workflow以原子批次處理可相容修改，讀取skipped或warning並修正。
7. 發布、啟用、對外訊息與不可逆操作依使用者已授權範圍執行。只有建置需求時新流程先不啟用。API key／Token由本人透過私密介面輸入，不放Code、聊天、範本或一般Execution輸出。

## 驗證

先靜態配置與資料鏈路，再執行無副作用測試。使用 execute_workflow 的 manual 模式驗證目前草稿，production只用於明確要執行發布版本時。觸發資料依節點要求提供，不能用pinData或模擬輸出冒充真實請求。

取得executionId後，用 get_workflow_execution讀回狀態及必要節點資料；started不是成功，未執行分支不能標通過。測邊界、錯誤輸入及重複情境應對應需求，使用隔離副本／資料，不改正式設定或傳訊給陌生收件人。外部操作結果不明先查紀錄，不盲目重試。服務接受不代表人已收件或結果已公開，依上層驗收規格分層確認。

若要求加錯誤通知，先說明共享錯誤工作流與同流程Error Trigger兩種方式，依實際授權決定，不默默新增通知。不得以自動重送掩蓋資料或去重缺陷。

## 交接

回報實際專案、工作流ID與URL、草稿／啟用版本狀態、設定來源、非秘密憑證名稱／ID、測試模式與Execution URL、通過／未通過／待驗證、未覆蓋分支及限制。將結果交回上層專案Skill，讓它依業務規則決定下一步。不在通用Skill寫入特定專案的股票、帳號或收件人。
