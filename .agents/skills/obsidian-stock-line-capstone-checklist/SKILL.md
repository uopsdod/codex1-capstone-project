# 美股通知知識庫：成果驗收

## 範圍與取證

這是n8n／LINE驗收之後的知識庫驗收。承接main的Vault、實際路徑與來源，透過Obsidian MCP讀回專案筆記、AI學習手冊及確實受影響的相關筆記，核對寫入結果與連結。唯讀查核，不重建筆記、不修改n8n、Webhook或排程、不重送LINE。

來源已附有日期的n8n證據即可驗收記錄是否正確；需要核對現況且n8n工具可用時只讀查詢。不能為了補知識庫證據要求重測整個作品；工具不可用明列尚未重新查核。

## 固定總結表

| 檢查項目 | 通過所需證據 |
| --- | --- |
| 專案內容 | 需求、工具分工、實際設定、工作流程、測試與排錯有來源；已完成留言改門檻時包含指令流程，不捏造未實作功能 |
| 目前設定及來源 | 記錄實際股票門檻、日期、來源與啟用狀態；已遷移則門檻來自共用表，股票／路由仍核對原節點；未遷移不要求額外建表 |
| 測試分層 | 隔離、真實行情、API接受、手機收到、草稿／啟用、自動執行分開；設定測試卡片不冒充達標推播 |
| 指令紀錄 | 已實作時包含「門檻改成 2%」「查詢門檻」用法、實際前後值、時間、回覆與證據；查詢事件寫入不誤記為改門檻 |
| 修改與歷史保留 | 目前值更新，原測試與人工內容保留；舊值清楚屬歷史，不把修改前成功當修改後成功。沒有修改則此項不適用，不要求製造一次修改 |
| 完成狀態一致 | 現況摘要、目前設定、最新自動紀錄、待辦及本人勾選彼此一致；保留人工確認，缺技術證據由Codex待查核 |
| 從AI學習手冊開啟專案 | MCP讀回手冊內的實際入口，解析並讀取目標專案，列出來源與目標路徑 |
| 從專案返回AI學習手冊 | MCP讀回專案中的返回連結，解析並讀取同一手冊，列出來源與目標路徑 |
| 版面與導覽 | 沒有檔名／正文重複同名H1；一個主要入口，無無用途的重複；相關筆記不存在時沒有虛構連結 |
| 截圖與附件 | 已保存附件存在且嵌入可解析；手機確認與附件保存分開。未提供圖片不造假，暫存失效不否定已取得確認 |
| 本人待辦與用語 | 只列需要本人完成的事，無丟回技術設定；中文功能名稱與交辦範例清楚，無裸英文Skill識別名稱或「學員」稱呼 |
| 秘密排除 | 無金鑰、Token、Channel secret、replyToken、完整User ID、私人信箱及敏感請求；憑證只記名稱用途 |

手冊雙向入口是固定成果，不能因聊天附了URI就判通過。確認缺連結／目標不存在標❌ 未通過；工具無法讀取標⏳ 待驗證，說明具體缺少能力。本人是否已點開查看另列，不影響工具已取得的連結證據。第三篇不存在可列不適用，不強制建立。

只讀檢查重複，不為驗收再寫兩次；有不同導覽用途的連結不因出現超過一次就判缺陷。截圖缺附件與缺手機確認分開判定，已有充分本人確認不重索取。空白圖片不當視覺證據。

## 判定與明確下一步

回報「檢查項目／結果／證據及限制」表，使用✅ 通過、❌ 未通過、⏳ 待驗證或待同步確認，不適用明寫。缺陷交回「美股通知專案筆記整理Skill」修正後再驗，不在本次查核默默改寫人工內容。若已完成的本人事項與舊文字矛盾，標待同步確認，不說本人沒做。

新門檻下首次自動執行尚未發生，只要筆記如實記錄，就能通過「測試分層／狀態記錄」；不是知識庫建置失敗。未做修改、沒有圖片或未重新讀n8n等限制，也不可假稱功能未完成。核心內容與雙向導覽已通過時，結論可為「✅ 專案知識庫整理完成」，另列真正待補內容。

最後提供工具回傳的專案筆記及AI學習手冊URI。需要本人看版面時給具體入口與查看範圍；已有確認不再要求重做。需要修正時給可直接貼上的中文需求，說明要修哪段、保留哪些內容；不要只留「之後再同步」一句話。
