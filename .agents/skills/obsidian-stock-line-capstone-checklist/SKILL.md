# 美股通知知識庫：成果驗收

先讀取main交接的Vault與實際路徑，再透過Obsidian MCP讀回專案筆記、學習手冊與受影響的第三篇筆記。這是成果檢查，不重建筆記、不修改n8n、不發LINE或啟用任何排程。

逐項核對：
- 專案需求、工具分工、股票門檻、行情來源、執行步驟、排程、去重與訊息格式有來源。預設值不能當實際值，無證據填待確認。
- 行情成功、LINE API接受、本人手機收到、已發布啟用、自動Execution各自記錄；歷史結果與目前查核日期分開。
- 測試附可取得的Execution連結、日期、真實／模擬／歷史模式；缺連結標未提供。API接受不等於手機收到。
- 專案連回學習手冊與第三篇，首頁有專案入口；連結用實際路徑，目標存在且同名歧義已處理。第三篇確實不存在時，依main已交付的替代方案驗收，不虛構連結。
- 操作截圖是真實取得且附件存在，嵌入路徑正確；未提供則待補，不偽造附件。使用者親眼看版面仍需本人確認。
- 更新保留原有實質內容及歷史測試，同名筆記／首頁入口未重複。只讀查核重複情況，不為驗收重寫兩次。
- 若已修改股票或門檻，筆記目前設定有修改後讀回證據，變更紀錄含前後值、原因、日期與測試；沒有實際改設定則該項待驗證，不擅自執行修改。
- 未包含秘密、完整收件人ID、私人信箱或敏感請求標頭；只記必要憑證名稱與用途。

用「項目／結果／證據及限制」表回報；結果為 ✅ 通過、❌ 未通過、⏳ 待驗證或待同步確認。說明用白話，提供Obsidian工具回傳URI與需修正項。讀不到就未確認，不宣稱成功。缺陷交回main修復再驗，不默默覆寫人工修改。使用者尚未查看截圖與內容時單列待本人確認；沒有實際變更紀錄不影響已完成基礎知識庫項目，但不能宣稱修改同步已驗證。

## 本次實作形成的驗收準則

- 以現行 JSON 設定節點及 static data 為來源，不沿用舊 Data Tables 模板要求。課程草稿可保留為歷史，不能當目前設定。
- Obsidian 已顯示檔名時，不再有同名正文 H1。筆記與交辦範例使用中文 Skill 名稱；行動清單只列需要本人完成的事項。
- 首頁有一個主要入口即可；同一連結出現在來源或有不同導航用途時不一概視為缺陷。只有無新增用途的重複入口才建議合併，不因連結數大於一就標系統功能失敗。
- 本人勾選手機收到、已提供截圖、已查看筆記，與正文保持一致。矛盾優先標 ⏳ 待同步確認，不能僅因舊文字未更新就判本人未完成。保留人工勾選，不以驗收代替本人確認。
- 修改練習本人已勾選、但缺技術前後值：本人完成狀態保留；「Codex 補齊變更證據」列待辦，不捏造設定、不再說本人尚未做。技術變更同步未驗證不影響基礎筆記整理的已完成項目。
- 截圖已提供但暫存檔失效，版面確認可沿用，附件保存單列待補；不重複索取已足夠的本人確認。若需實際嵌入而無可用檔案，再明確請補圖片。

最後提供工具回傳的專案筆記與 AI 學習手冊連結；需要本人確認時，只請查看這次更新的內容或補眼前缺少的證據，不整套重做。

## 固定列出的導覽驗收項目

總結表必須分列「從 AI 學習手冊開啟專案」與「從專案返回 AI 學習手冊」。每項以 MCP 讀回來源筆記中的實際連結，解析並讀取目標筆記，證據列出來源與目標路徑。兩項皆確認才可宣稱學習手冊入口完成；聊天中附上連結不能替代筆記內的入口。確認缺連結或目標不存在標 ❌ 未通過；工具無法讀取標 ⏳ 待驗證並說明缺少能力。本人是否已點開查看另列，不影響已取得工具證據的連結檢查。
