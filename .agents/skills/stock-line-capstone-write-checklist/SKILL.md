# LINE 留言修改門檻：成果驗收

## 範圍與取證

本單元只檢查n8n／LINE。Obsidian在之後執行：不讀寫筆記、不列筆記同步或缺失、不索取筆記連結，也不因尚無知識庫扣分。

承接 main 的本次交接，先讀實例context，再以MCP取得兩個工作流的草稿／真正啟用版、唯一共用設定、指令紀錄及相關Execution。LINE網址、Use webhook、Verify與redelivery依可用工具或有日期畫面核對。沿用足夠的本人確認與截圖，不要求重做。

只驗收，不修改門檻、啟用入口、重做Verify、重跑可能推播流程或重送LINE。模擬、隔離、真實HTTP、手機及自動執行證據分開；來源只是一份教材或工具名稱不能判定通過。讀不到時列具體未確認能力，不用瀏覽器冒充MCP驗收。

## 固定總結表

| 檢查項目 | 通過所需證據 |
| --- | --- |
| 原通知功能保留 | 同一原工作流，股票、憑證、本人路由、行情、卡片、去重與排程功能保留；不比較JSON格式、畫布位置或省略預設值 |
| 共用門檻 | 唯一有效列；遷移初始化有正式原值依據；沒有節點內第二份獨立門檻，無效設定停止不回退 |
| LINE來源驗證 | 真正原始body驗簽；錯誤／缺失簽章拒絕且不讀寫設定或回LINE；秘密只在受保護憑證 |
| 本人限定 | 本人一對一文字才處理；他人、群組、非文字不改設定，證據註明隔離或真實 |
| 指令格式 | 「門檻改成 2%」及小數可解析；「查詢門檻」可用；錯誤格式、範圍外與附帶內容不修改 |
| 寫入與查詢 | 更新前後及寫後讀回一致；查詢不改門檻，但可寫事件／去重紀錄；失敗不回覆成功 |
| 重送與順序 | 持久事件紀錄、版本條件提交；隔離整合證據顯示重送不重複處理、舊指令不覆蓋新值；不把此項擴大成任意高併發保證 |
| LINE回覆 | 正確事件reply API；接收、提交、回覆API接受與失敗狀態可區分 |
| 手機修改與查詢 | 本人實際傳入的Execution與前後值吻合，手機修改／查詢回覆各有本人確認或清楚截圖；改表不算手機測試 |
| 原通知採用新值 | 不推播驗證顯示計算、IF與Flex採同次共用門檻，修改指令未觸發股價推播 |
| 正式入口 | 已取得上線指示、指令正式版啟用，Production URL及Use webhook正確，Verify成功；草稿不當成已上線 |
| 原排程保留 | 原啟用狀態、台灣週二至六夏令05:00／冬令06:00與自動切換功能保留 |
| 修改後首次自動執行 | 必須有修改後的實際排程Execution；手動、收件測試、舊門檻自動成功不能代替 |

若本人另行要求股價測試卡片，額外列收件及版面結果，依本次截圖確認；沒有要求就不強制補送、不因沒有達標股票判失敗。明標測試卡片不等於真實達標通知。

## 判定及限制

回報固定使用「檢查項目／結果／證據及限制」，結果為✅ 通過、❌ 未通過、⏳ 待驗證，範圍外明寫不適用。說明白話，不用科學記號、裸參數或極微小精度差異作額外門檻。保留人工確認，文字矛盾列待同步確認，不推翻本人已做的事。

核心鏈路已實測時，結論可為「✅ 修改與查詢門檻核心功能驗收通過」。首次自動排程尚未發生，獨立標待驗證，不把整個作品說成未完成，也不宣稱所有項目通過。極端併發、實際資料庫故障等未實測分支如實列限制，不能從靜態程式推定全部已通過。

Verify只驗證入口，不證明手機收件；設定已更新但reply失敗也不能說完全沒更新。redelivery關閉時不承諾LINE自動重送503。推播結果未知先查紀錄，不盲目補送。
