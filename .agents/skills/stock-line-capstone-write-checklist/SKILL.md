# LINE 留言修改門檻：成果驗收

## 範圍與證據

只驗收既有結果，不為驗收修改正式門檻、啟用入口、覆蓋 Webhook 或重送 LINE。先承接建置交接，使用 n8n MCP 讀回兩個工作流、真正啟用版本、共用設定及相關 Execution。歷史教材、工具名稱、草稿或本人說已操作，不能替代資料與執行證據。缺工具時指出能力與下一步，不以瀏覽器驗收冒充 MCP 完成。

## 固定檢查項目

| 項目 | 通過所需證據 |
|---|---|
| 原功能保留 | 原工作流身分不變，股票、憑證、本人路由、行情、卡片、去重與排程功能保留；比較功能而非 JSON 格式 |
| 共用設定 | 唯一門檻列有效，初始化／遷移有原值證據，無兩份獨立可調門檻，讀取失敗不回退 |
| LINE 來源驗證 | 原始 body 驗簽實測；錯誤／缺失簽章不讀寫設定、不回覆，秘密未進入一般參數及輸出 |
| 本人限定 | 本人一對一文字才可操作；其他人、群組、非文字不改設定 |
| 指令格式 | 合法整數／小數可解析；錯誤格式、超出範圍與附帶內容不改資料，給本人正確範例 |
| 寫入與查詢 | 更新後讀回一致；查詢只讀；資料失敗不回覆成功 |
| 重送與順序 | 持久處理紀錄與實際控制；多事件／重送不重複寫回覆，舊事件不覆蓋較新設定；不能以先查後寫冒充原子保證 |
| LINE 回覆 | reply API 使用對應事件，HTTP 接收、設定更新與回覆 API 接受分開有證據 |
| 手機指令 | 本人傳送指令的對應 Execution 與資料更新吻合；本人確認更新及查詢回覆。Codex 直接改表不算此項 |
| 原通知採用 | 不推播驗證顯示計算、IF 與 Flex 使用同一新門檻；修改本身未觸發行情推播 |
| 正式入口 | 經本次上線指示才啟用，Production URL、LINE Verify、Use webhook 與真正啟用版讀回一致；草稿可完成建置但上線項待驗證 |
| 排程與修改後證據 | 原排程及時區保留；新門檻下的自動執行有實際 Execution 才通過，不沿用修改前證據 |
| 專案筆記同步 | 原筆記記錄設定來源、指令用法、前後值、時間、測試與待驗證，歷史與學習手冊入口保留；不存在筆記時列不適用 |

有效空 events 的 Verify 成功只證明入口驗證，不代表手機指令成功。資料已更新但 LINE 回覆失敗，分別記錄，不能整體宣稱未修改或盲目重試。新版行情卡片手機收件如無新證據，獨立列待驗證；沒有達標股票正常不發，不算故障。

## 總結與下一步

總結表固定為「檢查項目／結果／證據及限制」，使用 ✅ 通過、❌ 未通過、⏳ 待驗證；範圍外明寫不適用。證據為工具讀回或有日期的 Execution，本人畫面確認註明來源。未實測分支不寫通過，不能保證所有帳號皆可安全驗簽。保留人工勾選，狀態矛盾列待同步確認，別推翻本人已確認事項。

缺陷交回「LINE 留言修改門檻建置 Skill」修正再驗，不在此自動修復正式資料。只有缺少本人手機證據時，簡短引導傳指令或提供回覆截圖；工具可自行取得的資料由 Codex 查，不要求重做整套測試。
