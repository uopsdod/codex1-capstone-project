# 驗收與交接

依可取得證據逐項驗證，未做就待驗證：
1. 沿用單元 2 的 MCP 建立、執行與讀回結果證據；缺能力如實記錄，不重做固定文字輸出測試。
2. 三檔真實日線：兩個日期、價格、獨立核算 changePct，Data Table 的執行快照。
3. 用主流程同一份讀表／計算／IF 邏輯隔離測試兩個門檻，結果隨值改變；僅數字剛好一致不算驗證來源。模擬資料明標、不得發 LINE 或改正式設定。補測一般達標與未達標、上漲、持平、非法設定與壞行情阻擋；設定來源依目前 JSON 範本核對。極小幅度超過門檻的小數精度差異已由使用者接受，不納入驗收或未通過項目。
4. 空集合不發、單檔與多檔 Flex JSON 動態正確；LINE validate 成功；bot/info 與 push 接受各自記錄；手機收件／版面要學員回覆，不能代勾。
5. 隔離驗證正式同股票日期去重、不同日期、手動不寫正式紀錄；模擬接受／失敗不冒充真實推播測試。記錄失敗、未知推播結果及並行限制列明。
6. 發布啟用另驗收：讀回啟用版本、實際排程、時區、讀表鏈路。草稿與啟用版依功能比較：股票、門檻、收件人、憑證、行情／通知邏輯、去重與排程一致即可通過。版本編號、節點位置、備註、分組或JSON格式差異不影響通過；不能僅因sameAsDraft=false就標待確認。若有功能差異，分列具體項目與影響。首次自動 Execution 未發生寫「已啟用，首次自動執行尚未驗證」。不為驗收改排程或重發。

最後交接：查核日期、完成與待完成、專案名稱、工作流ID及URL、表名／固定鍵及URL、非秘密憑證名稱與類型、股票與名稱、目前門檻與嚴格規則、排程與所在地時間、草稿／啟用版本狀態、訊息格式、正式／手動去重差異、每筆測試時間／模式／Execution URL／結論、手機回覆、問題與解法、如何改設定。通知對象只稱「本人 LINE」，不輸出完整User ID。沒有證據不填成功，歷史教材僅為需求來源。可供 Obsidian 讀取的交接檔不得包含秘密、完整請求標頭或收件人ID。
