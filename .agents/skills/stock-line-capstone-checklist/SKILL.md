# 美股通知：成果驗收

針對 main 交付的同一工作流ID驗收，先讀實例 context，取得目前設定、草稿與真正啟用版本、資料表及本次Execution。只讀回有來源的證據，不能用需求預設或歷史教材填成功。

## 檢查清單

依 [驗收規格](references/verification.md) 核對以下項目：
- 專案與來源：手動及排程入口確實接到設定表，同一固定鍵只有一筆，本次執行門檻與股票由讀表快照一路傳遞；沒有固定回退值。
- 行情：每檔兩個有效交易日期、收盤價、市場與USD，獨立核算 changePct。缺資料與錯誤不能補0；正式行情日期不符當日要略過。
- 條件：原精度 changePct < -threshold；相等不通知，0有效，上漲持平不發；非法設定與壞行情停止。用已完成隔離測試證據確認兩個不同門檻確實影響判斷。
- 訊息：只含達標股票，mega窄版、日期與價格、兩位小數、箭頭、動態門檻及檔數對應同次Execution；單檔／多檔／空集合結果分開。
- LINE：bot/info、Flex validate、push接受與本人手機收件四層分開。本人未確認的手機送達與版面仍待驗證。
- 去重：正式按股票與交易日期持久去重，LINE接受後才記錄；手動不影響正式去重。不能把查再寫說成原子鎖，並行及不明結果限制要列出。
- 上線：真正發布版的時區、平日17:00排程與讀表鏈路；是否啟用、自動Execution是否已發生分列。未要求上線且未啟用不是功能錯誤，標「尚未啟用」。
- 交接：工作流／設定表／Execution連結、最新設定、待辦與修改方式完整，不包含秘密或完整User ID。

## 驗證邊界

先檢查既有證據，不為了驗收重送LINE、改正式門檻、發布或啟用。缺失的無外部副作用測試可於未啟用隔離副本補做，沿用主工作流同一邏輯，標明模擬範圍。需要真實推播或改正式設定時提出具體測試，由本人授權後才做，不把驗收要求當作額外發送授權。

找到缺陷就列出位置、影響及建議，由 main 修復後再驗；不要為修正同一節點刪除重建，不默默覆寫正式版本。資料讀不到時標未確認，不把權限問題當系統正常。

## 結果

以「項目／通過、未通過或待驗證／證據及限制」表交付。只在所需證據齊全時稱通過。特別列出手機與自動觸發尚待本人或未來執行確認的項目，不為等排程阻塞其他交付。每筆測試註明時間、真實／模擬／歷史及Execution連結。最後提供目前股票、門檻、排程、發布狀態與下一步，可交給 Obsidian Skill 同步知識庫。
