# LINE 留言修改門檻：功能建置

## 成果與分工

新增或沿用「LINE 留言修改跌幅門檻」工作流，支援「門檻改成 3%」及「查詢門檻」。同一設定供指令工作流與原股價工作流使用。只管理門檻，修改本身不查行情或觸發股價推播。Codex 完成技術設定；本人只處理登入、必要授權、私密輸入與手機指令／畫面確認。

先承接 $stock-line-capstone-write-prerequisite 的本次證據，缺項先補。工作流技術建置在同一對話使用 $n8n-workflow-builder。此 Skill 明確允許將單向通知的設定節點門檻遷移到共用設定表；只遷移必要門檻，不重建原通知工作流，不修改共用 JSON 範本。若再次執行，沿用既有結果，不新增同用途流程或重置設定。

實作前讀取 [已實測建置路徑](references/implementation.md) 與其中的指令處理程式，沿用已驗證的原始資料、受保護憑證、版本條件更新及隔離測試方式；本次實例能力仍需核對，不硬編碼老師的資源。

## 1. 可回復的設定遷移

- 保存原工作流草稿、啟用版本、連線、門檻、排程及非秘密設定，回復資料不要提交課程 repository 或輸出到聊天。保留憑證引用，秘密不匯出。
- 同專案建立或沿用 `stock_alert_settings`，以 `setting_key=stock_drop_threshold` 表示唯一設定列，包含數字 `threshold_pct`、`updated_at`。初始化使用原工作流實際值。已有不同值、缺列或重複列時先釐清；不以預設掩蓋問題。保留既有其他欄位；秘密不存表中，本人 User ID 沿用受限的既有路由設定且不公開輸出。
- 原通知工作流每次開始讀取唯一有效門檻，範圍大於 0 且小於 100。計算、IF 與 Flex 摘要使用同一次讀取的快照，執行途中修改於下次生效。原設定節點可保留股票與收件人，移除其獨立可調門檻，避免雙重來源。缺列、重複列、無效值或讀取失敗時停止，不偷偷回退舊值。
- 保留行情、股票、收件人、卡片版型、去重與排程時區。先用隔離、不推播的路徑測試讀取與傳遞；不執行會發送行情的正式手動路徑作驗收。遷移期間避免已啟用工作流讀到半套設定。

## 2. 安全接收及指令處理

- 依本次實際節點能力實作驗簽。先對未改動的原始 request body 計算 HMAC-SHA256、Base64，比對 `x-line-signature`；不能解析後重新序列化來驗簽。Channel secret 只用受保護的秘密機制，不能置入 Code、Set、Variables、Data Tables、網址、課程檔案或一般 Execution 輸出。無安全方案就停止此延伸，不降低保護，也不動原單向通知。
- 缺失／錯誤簽章拒絕，無設定讀寫或 LINE 回覆。有效的空 `events` 驗證請求回應成功；及時回應 HTTP，接收成功不等於業務處理成功。
- 逐一處理多個 events，只接受已確認本人一對一文字訊息。其他人、群組、非文字事件不修改設定，不回覆陌生使用者。
- 完整匹配「門檻改成 數字%」或「查詢門檻」，對外以「門檻改成 2%」為預設提示，保留舊格式「門檻 2%」相容；可接受前後空白及省略百分號；數字大於 0、小於 100，最多兩位小數。拒絕負值、0、100、科學記號、NaN 及附帶其他內容。不用模型猜測聊天。本人格式錯誤時回覆正確範例且不改資料。
- 更新前讀取原值，僅更新該列門檻與修改時間，寫後讀回核對。成功才回覆「已將跌幅門檻從 1.5% 改為 3%，下次股價檢查起生效。」數值由本次資料產生。「查詢門檻」只讀取並回覆。資料失敗不回覆更新成功。
- 用事件的 replyToken 與既有 Token 憑證呼叫 LINE reply API，不改成 push。持久記錄 `webhookEventId`、事件時間、前後值及處理階段；避免重送重複寫入、重複回覆及舊事件覆蓋新值。採實際可用的序列化或併發控制，不能宣稱普通先查後寫有原子保證；無法保證順序時明列阻礙，不宣稱可正式使用。分開記錄已寫入／回覆已接受／失敗，寫入前不標成功。回覆結果不明不盲目重送已使用的 replyToken。

## 3. 測試、發布與本人操作

1. 在隔離資料上測正確指令、小數邊界、錯誤格式、錯誤／缺失簽章、非本人、群組、非文字、空 events、多事件、重送、亂序及資料讀寫失敗。不用真實個資／秘密作分享測試資料，不寫正式測試門檻或向他人發訊息。
2. 確認原通知計算與卡片使用共用值；不得改用更寬鬆的數字精度檢查作額外課程門檻。記錄 Execution 與限制。
3. 使用者明確要求上線後才發布新入口並設定正式 Production Webhook URL／Use webhook；只要求建置時先交付未啟用草稿。原通知若已啟用，在本次遷移範圍內驗證後發布更新並保留原啟用狀態；原先未啟用就維持未啟用。Webhook 有其他用途先確認整合方案，不直接覆蓋。透過 LINE Verify 後讀回真正啟用版本與 Webhook 設定。不要以 Verify 成功宣稱手機指令通過。
4. 請本人在聊天室傳送自己選定的「門檻改成 數字%」，說明這是要保存的正式新值；等待回報後讀取對應 Execution、資料表與回覆結果，再請傳「查詢門檻」。不由 Codex 改表冒充手機操作，不強迫測試值為 0.5%，不自行恢復舊值。本人傳入的合法指令可由工作流回覆確認。
5. 以隔離不推播路徑驗證原通知使用新門檻。另有明確發送指示才執行可能推播的股價流程；沒有達標股票正常不發。新門檻下的手機行情卡片與首次自動排程各自列待驗證。

## 首次設定與既有入口

課程預設為第一次設定 LINE Webhook：確認欄位尚未設定後，依建置／上線階段填入新工作流的正式網址。不要預設每個人都有舊入口、404 或跨實例問題。只有實際發現既有 URL 才檢查用途及處理替換／整合；本人確認的舊練習情境是條件分支，不當作所有人的必要操作。不因入口空白判定前置失敗，正式網址待新工作流完成後設定。

## 收尾：發布上線與手機實測

建置測試通過後，不只說「下一步發布並手機測試」。依本次狀態提供可直接操作的下一步；若已授權上線或已完成發布，不重複要求相同授權，不要求重新貼一次指令。

### 尚未取得上線指示

交付工作流及測試結果後，提供以下可直接貼上的指令；這是待本人送出的指令範例，不當作當下已授權：

ask """
請發布並啟用剛建立的「LINE 留言修改跌幅門檻」工作流，將這個工作流的正式 Webhook 網址設定到我的 LINE 官方帳號，啟用 Use webhook 並執行 Verify。
保留原股價通知的股票、門檻、排程與啟用狀態。若 LINE 已設定其他 Webhook，先確認用途及是否可替換，再處理。
驗證成功後，請明確告訴我在手機 LINE 要傳送哪一句指令，等待我操作後，再讀取執行紀錄確認結果。
"""

### 上線成功後

1. 重新讀取正式啟用版本、LINE 的正式網址及 Use webhook，確認 Verify 成功，再請本人到自己的官方帳號聊天室傳送「門檻改成 1.5%」，或換成本人要保存的門檻。1.5%只是教學範例；若本次已選定2%等數值，沿用該選擇，不擅自換回範例。清楚說明這是正式要保存的新值，修改本身不立即發送股價通知。
2. 每次只交接眼前一步。請本人傳送後回覆「已傳送修改門檻指令」，並告知手機是否收到修改成功的回覆；等待本人操作，再讀取對應Execution、共用設定與回覆紀錄，確認本次前後值，不代傳訊息或直接改表冒充手機測試。
3. 修改確認後，再明確請本人在LINE傳送「查詢門檻」，回報收到的數值。等待回報後，核對查詢Execution與設定；API接受與手機確認分開記錄。
4. 不因測試結束自動恢復門檻。遇到錯誤由Codex先查紀錄，不要求反覆傳送或盲目重發。手機尚未操作時保持待本人確認，不預先宣稱收件通過。
5. 實測完成後提供工作流與測試證據連結、非秘密交接摘要，明確交接「請執行 stock-line-capstone-write-checklist Skill。」作成果驗收。Obsidian知識庫留待後續單元執行，不在這一步自動同步筆記。
