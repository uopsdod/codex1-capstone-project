# 美股通知專案筆記模板

依既有格式調整，不逐字填入老師設定。未知值標待確認，未實作功能列不適用，不造證據。檔名可用「Capstone：我的美股跌幅 LINE 通知.md」或沿用實際既有路徑；正文不重複同名H1。

> 更新與查核：實際日期、時區、來源與本次是否重新讀取現況。知識庫整理在n8n／LINE驗收之後，不代表重新執行工作流。

## 專案需求與分工
- 解決什麼問題、追蹤範圍、通知條件與完成標準。
- Codex代辦建置／查核，n8n執行行情／指令／通知，Obsidian保存設定與經驗；本人只處理必要登入、秘密、選擇及手機確認。

## 目前設定
只保留一份權威現況表，其他階段摘要引用它或標當時日期，避免多處出現互相矛盾的「目前」。
- 查核時間、實際股票／名稱、門檻、本人路由只記已確認不記完整識別。
- 已遷移：門檻來源為共用表，股票／路由為原設定節點；表內保留但未使用的舊欄位說清楚。未遷移：記原節點，不要求建表。
- 行情來源、Flex格式、憑證名稱／用途；區分發送access token與接收驗簽Channel secret，不保存值。
- 台灣每週二至六夏令05:00／冬令06:00與自動切換；補記底層紐約排程，不把台北固定時間套全年。
- 原通知與指令工作流各自的草稿／真正發布版／啟用狀態、正式Webhook及Verify（只在已實作時）。
- 最新自動執行依哪一版股票門檻、來源日期；新值尚無自動紀錄就明記待驗證，不留舊值當現況。

## 股價通知流程
觸發 → 讀本次設定快照 → 取兩個有效交易日日線並驗證 → 計算與判斷 → 正式去重 → Flex推播 → LINE接受紀錄。手動與自動去重差異依實際版本記錄。

## LINE留言改門檻流程（已實作才加入）
- 「門檻改成 2%」為句型示例；目前門檻填實際讀回值，不因示例寫成2%。「查詢門檻」查看目前值。
- 原始資料驗簽 → 核對本人一對一文字 → 解析指令 → 版本條件提交／讀回 → reply回覆與事件紀錄。
- 修改保存後由下次股價檢查採用，不立即推播行情。查詢不改門檻，但可寫事件紀錄。
- 本次首次設定或既有入口替換的處理、redelivery狀態與已確認限制；不把老師的舊實例情境當必要步驟。

## 測試與收件紀錄
用「日期／範圍與模式／預期／實際／Execution或本人來源／限制」表，保留歷史：
- 原通知：真實行情、IF與卡片、格式validate、push接受、手機卡片與首次自動，各自記錄。
- 指令：隔離格式／本人限定／重送亂序、真實HTTP簽章、LINE Verify、本人修改前後、查詢reply接受與手機回覆，各自記錄。
- 額外授權的設定測試卡片：實際行情日期、股票、正式門檻、測試標示、API及本人截圖；不當正式達標或自動證據。
- 缺Execution連結標未提供，不捏造；同一secret自行簽fixture與LINE真正請求的範圍不同。

## 問題與解法
現象 → 可證實原因／推測 → 處理 → 新證據與限制。可依本次實際經驗記：瀏覽器服務未接通後重開Codex恢復；MCP手動輸入無raw body改實際Test URL；Crypto不保留binary；Verify逾時但Execution成功後再驗證；舊表來源差異。沒有遇到就不假稱發生。

## 變更紀錄
記實際日期、原因、修改前後、設定來源／版本、證據、仍待驗證。相同結果再整理不重複新增、不偽造查核日期；不用整篇複製舊筆記。

## 待驗證與限制
只列仍缺證據的功能項，例如新門檻下首次自動執行或未測失敗分支，標由Codex後續核對。已成功收件／修改／查詢不留在等待操作。

## 需要使用者完成的事項
只按本次缺項產生，不把下列示例全數變成待辦；保留既有本人勾選：
- 在手機確認眼前尚未確認的回覆或卡片，或提供需保存的截圖。
- 在Obsidian從AI學習手冊開啟專案，再從專案返回手冊，查看筆記與附件。
- 若尚未做修改練習：練習修改一次追蹤股票或跌幅門檻，再請Codex同步更新專案筆記，保留修改前後的紀錄。
技術設定、測試、匯入附件、讀回與筆記維護由Codex負責，不放本人清單。

## 下次可用的交辦方式
請Codex修改原美股通知的股票／門檻並驗證，保留其他功能；已完成留言功能時也可在LINE傳「門檻改成 自己的數值%」。再請Codex整理原專案筆記的目前設定與變更紀錄，保留歷史。使用中文功能名稱，不填英文Skill識別名稱或「學員」稱呼。
