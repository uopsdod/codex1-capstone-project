# 美股跌幅 LINE 通知核心功能建立

## 固定成果與分工

在學員自己的 n8n 專案建立「美股跌幅提醒｜LINE個人通知」。全新專案預設 TSM、NVDA、GOOGL，跌幅嚴格超過 2.5% 才通知。比較最近兩個有效交易日收盤價，紐約平日 17:00 檢查，沿用 JSON 範本的 LINE 文字訊息送給本人。既有專案保留實際設定，不用預設覆蓋。

Codex 完成工具發現、範本匯入、必要設定、連線、憑證綁定與驗證。學員只負責登入、註冊與條款、私密輸入秘密、加好友及手機收件確認。每次只交接眼前必要的一件事，完成後接續，不整套退回人工設定。

直接使用隨附 [工作流 JSON](assets/codex_ch05_n8n_股價波動_LINE通知_workflow.json) 作為固定建置來源，不從零另寫工作流。沿用範本的「通知門檻設定」節點與 static data 去重，不自行改成 Data Tables 或 Flex 卡片。範本原檔不填入任何學員收件人或憑證；個人設定只寫入學員的 n8n 實例。金鑰不放聊天、一般參數、程式、Data Tables 或分享檔。不要讀出既有秘密搬移，不索取 n8n Public API Key、不為課程升級方案。

## 匯入與設定原則

參照 [原始設定指引](references/original-workflow-setup.md) 的匯入與配置流程；本課程的手動測試範圍依下節及學員當次指示。匯入一次；已有本次範本結果就接續設定，不重複建立。先完成全部結構與可預填欄位，缺少的憑證連接先列待辦，最後集中引導；prerequisite 已驗證的憑證直接沿用，不要求重做。

清除不屬於學員的個人資料、憑證參照、pinData 與執行資料。確認本人 User ID 與 Channel 屬同 Provider 範圍，且已加好友、未封鎖；Codex 回填「通知門檻設定」，不要求學員改程式或接線。User ID 是通知路由，不是 Token。

Twelve Data 由 Query Auth 注入 apikey；LINE 由 Bearer Auth 注入 Authorization，不重複加入一般參數或標頭。介面支援時限制憑證服務網域為 api.twelvedata.com／api.line.me。單向通知不需要 Channel secret 或 Webhook；金鑰配置不是 OAuth。

## 技術實作分工

本 Skill 負責美股通知的業務規格與整合順序。n8n 的節點建置、SDK配置、修改與Execution驗證，請讀取並使用同課程的 $n8n-workflow-builder。將隨附工作流 JSON、[範本使用規格](references/build-spec.md)、prerequisite交接的專案／憑證與已授權測試範圍交給它；取得實測結果後，依本專案規則判斷是否可進入下一階段。不要求學員另外交辦通用Skill；由main在同一對話接續使用。若未安裝，先從同repository安裝，不宣稱已使用不存在的Skill。

## 手動測試範圍

學員要求使用本 Skill 建立並驗證本人通知專案時，核心實作包含手動執行一次：符合條件時發送到目前設定且已確認的本人 LINE；沒有符合股票時先說明，再提出具體測試方案，不偷偷改正式門檻。不要求學員另外貼一段相同範圍的授權文字。若學員只要求閱讀、修改 Skill 或檢查設定，不因此執行或發送。

臨時門檻、歷史重播、其他收件人或追加發送不包含在這一次測試內，先說明具體方案並取得學員指示。排程啟用依後續上線指示處理。

## 執行順序

前置帳號、MCP與憑證由 $stock-line-capstone-prerequisite 檢查。讀取其本次交接，沿用已驗證的帳號與憑證，不重複要求登入或填秘密；若未完成，先接續前置檢查。

1. 承接單元 2 已完成的環境建置，發現當前 n8n MCP 能力，讀取實例 context、官方 SDK、節點型別與驗證方式。若 MCP 工具尚未載入或連線失敗，回報具體原因並回到 TXT 的連線步驟，不改用瀏覽器冒充 MCP 成功。已連線時直接開始核心功能。
2. 沿用單元 2 透過 MCP 建立並執行工作流的本次驗收證據，不重做連線驗收，不要求固定文字輸出。若沒有證據，依 TXT 完成建立與執行的 MCP 驗收後接續。
3. 找出同專案既有工作流、憑證與啟用版本，保存可回復的非秘密設定。多個候選才問學員。從零重現時建立隔離教學副本，不改動既有正式收件、排程與去重狀態。
4. 讀隨附工作流 JSON 與 [範本使用規格](references/build-spec.md)，以原 JSON 匯入未啟用工作流。若 MCP 只接受 SDK，將原節點、parameters、connections 與 settings 忠實轉換，保留原業務邏輯與文字通知；不重新設計。綁定既有 Twelve Data 憑證，先隔離執行行情查詢與計算，再用真實行情核算日期、價格及 changePct，驗證「通知門檻設定」來源。
5. 準備 LINE 帳號與憑證，沿用 prerequisite 的唯讀 bot/info 成功證據，確認原範本的 LINE 文字訊息；依上述手動測試範圍只執行一次，不重複詢問已明確交辦的相同範圍。沒有達標股票時回報正常未發，不偷偷調門檻。若需臨時門檻或歷史重播，先說清楚具體測試取得授權，依規格隔離並還原。
6. 等學員確認手機收到及文字內容後，依學員上線指示發布、啟用；只有「建立」的要求不自動視為每日啟用授權。讀回真正啟用版本，不只看草稿。首次排程未發生仍可交付，明列自動執行待驗證。
7. 完成核心實作後產生非秘密交接摘要：工作流、設定節點、憑證引用、股票與門檻、排程與啟用版本、本次測試Execution、手機回覆及待辦。告知下一步執行 $stock-line-capstone-checklist 做成果驗收，再交給 Obsidian Skill 整理；不能用歷史教材的成功代替本次驗證。

## 修改與延伸

改股票或門檻時更新同一工作流的「通知門檻設定」節點，讀回確認。沿用範本的有效範圍 0 < threshold < 100，不改共用 JSON 原檔或另建設定表。新股票確認市場、USD 與名稱，未確認中文名稱就顯示代碼，不捏造。下一次執行採用新值，執行中保持原快照。改完交接 Obsidian 更新目前設定與變更紀錄。

只有學員明確要求 LINE 留言修改門檻時，讀 [LINE 指令延伸](references/line-command-extension.md)。不把該模式當作主線前置條件，不因現有方案不能安全驗簽而停住單向通知。

## 回報

繁體中文。先說明本次是否真實行情、是否發 LINE、是否更改正式設定，再以「檢查項目／狀態／白話說明」表回報：通過、未通過、待驗證。正確阻擋壞資料可通過；沒執行的分支是待驗證。連結放最後「參考資訊（選看）」。不讓學員研究 Execution，Codex 自行讀取核對。出錯先修復必要範圍；推播結果不明時不盲目重送。
