# 美股跌幅 LINE 通知核心功能建立

## 固定成果與分工

在學員自己的 n8n 專案建立「美股跌幅提醒｜LINE個人通知」。全新專案預設 TSM、NVDA、GOOGL，跌幅嚴格超過 2.5% 才通知。比較最近兩個有效交易日收盤價，紐約平日 17:00 檢查，以 mega 窄版 LINE Flex 卡片送給本人。既有專案保留實際設定，不用預設覆蓋。

Codex 完成工具發現、建表、節點、程式、連線、憑證綁定與驗證。學員只負責登入、註冊與條款、私密輸入秘密、加好友及手機收件確認。每次只交接眼前必要的一件事，完成後接續，不整套退回人工設定。

這份 Skill 使用 Data Tables 與 Credentials，不沿用舊 workshop 的 Variables 路線。金鑰不放聊天、一般參數、程式、Data Tables 或分享檔。不要讀出既有秘密搬移，不索取 n8n Public API Key、不為課程升級方案。

## 技術實作分工

本 Skill 負責美股通知的業務規格與整合順序。n8n 的節點建置、SDK配置、修改與Execution驗證，請讀取並使用同課程的 $n8n-workflow-builder。將 [建置規格](references/build-spec.md)、prerequisite交接的專案／憑證與已授權測試範圍交給它；取得實測結果後，依本專案規則判斷是否可進入下一階段。不要求學員另外交辦通用Skill；由main在同一對話接續使用。若未安裝，先從同repository安裝，不宣稱已使用不存在的Skill。

## 手動測試範圍

學員要求使用本 Skill 建立並驗證本人通知專案時，核心實作包含手動執行一次：符合條件時發送到目前設定且已確認的本人 LINE；沒有符合股票時先說明，再提出具體測試方案，不偷偷改正式門檻。不要求學員另外貼一段相同範圍的授權文字。若學員只要求閱讀、修改 Skill 或檢查設定，不因此執行或發送。

臨時門檻、歷史重播、其他收件人或追加發送不包含在這一次測試內，先說明具體方案並取得學員指示。排程啟用依後續上線指示處理。

## 執行順序

前置帳號、MCP與憑證由 $stock-line-capstone-prerequisite 檢查。讀取其本次交接，沿用已驗證的帳號與憑證，不重複要求登入或填秘密；若未完成，先接續前置檢查。

1. 承接單元 2 已完成的環境建置，發現當前 n8n MCP 能力，讀取實例 context、官方 SDK、節點型別與驗證方式。若 MCP 工具尚未載入或連線失敗，回報具體原因並回到 TXT 的連線步驟，不改用瀏覽器冒充 MCP 成功。已連線時直接開始核心功能。
2. 沿用單元 2 透過 MCP 建立並執行工作流的本次驗收證據，不重做連線驗收，不要求固定文字輸出。若沒有證據，依 TXT 完成建立與執行的 MCP 驗收後接續。
3. 找出同專案既有工作流、資料表、憑證與啟用版本，保存可回復的非秘密設定。多個候選才問學員。從零重現時建立隔離教學副本，不改動既有正式收件、排程與去重狀態。
4. 讀 [建置規格](references/build-spec.md)，先完成資料表與 Twelve Data 行情；此階段不索取 LINE 資料。用真實行情核算日期、價格及 changePct，驗證門檻來源，成功才進入 LINE。
5. 準備 LINE 帳號與憑證，先唯讀 bot/info，再驗證 Flex JSON；依上述手動測試範圍只執行一次，不重複詢問已明確交辦的相同範圍。沒有達標股票時回報正常未發，不偷偷調門檻。若需臨時門檻或歷史重播，先說清楚具體測試取得授權，依規格隔離並還原。
6. 等學員確認手機收到及版面後，依學員上線指示發布、啟用；只有「建立」的要求不自動視為每日啟用授權。讀回真正啟用版本，不只看草稿。首次排程未發生仍可交付，明列自動執行待驗證。
7. 完成核心實作後產生非秘密交接摘要：工作流、資料表、憑證引用、股票與門檻、排程與啟用版本、本次測試Execution、手機回覆及待辦。告知下一步執行 $stock-line-capstone-checklist 做成果驗收，再交給 Obsidian Skill 整理；不能用歷史教材的成功代替本次驗證。

## 修改與延伸

改股票或門檻時更新同一固定鍵設定列與 updated_at，讀回確認。門檻可為 0（所有實際下跌符合），有效範圍 0 <= threshold < 100；不新增第二列或改 Code 寫死值。新股票確認市場、USD 與名稱，未確認中文名稱就顯示代碼，不捏造。下一次執行採用新值，執行中保持原快照。改完交接 Obsidian 更新目前設定與變更紀錄。

只有學員明確要求 LINE 留言修改門檻時，讀 [LINE 指令延伸](references/line-command-extension.md)。不把該模式當作主線前置條件，不因現有方案不能安全驗簽而停住單向通知。

## 回報

繁體中文。先說明本次是否真實行情、是否發 LINE、是否更改正式設定，再以「檢查項目／狀態／白話說明」表回報：通過、未通過、待驗證。正確阻擋壞資料可通過；沒執行的分支是待驗證。連結放最後「參考資訊（選看）」。不讓學員研究 Execution，Codex 自行讀取核對。出錯先修復必要範圍；推播結果不明時不盲目重送。
