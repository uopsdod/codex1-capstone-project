# 股價 LINE 通知設定

## 原則
以使用者提供的 JSON 為工作流來源，先讀取再配置。範本已包含行情請求、跌幅計算、訊息、去重與排程，不逐一重建或重複定義參數。不要求固定檔名、路徑或作業系統。

Codex 負責匯入、填參數、綁定憑證與驗證；使用者只負責必要登入、秘密輸入與確認通知對象。不要求使用者改程式、接線或把秘密貼到聊天。先建好全部結構與可預填設定，再集中引導憑證連接。

## 1. 匯入與配置
- 確認工具或瀏覽器所連的 n8n 實例與帳號正確。匯入一次，已有本次結果就繼續設定，不建立重複工作流。
- 保留 JSON 的股票、門檻、紐約時區、排程及未啟用狀態；使用者另有明確需求時才調整。清除不屬於使用者的憑證參照、個人資訊、pinData 與執行資料。
- 「通知門檻設定」的 `LINE收件人UserID` 留待確認後由 Codex 回填。User ID 是通知路由，不是 token；不得編造，也不要求使用者修改程式。若無法自動取得，才引導使用者從自己的官方介面確認。確認該 ID 與 Channel 屬於相同 provider 範圍，且對方已加官方帳號好友、未封鎖。
- 兩個 HTTP 節點已選好認證類型，但未綁定憑證。已有正確憑證可重用；缺少連接先記錄待辦，不打斷建置。

## 2. 驗證與操作規範
- 連接後先隔離執行行情查詢與計算；再以 LINE 憑證呼叫 `GET https://api.line.me/v2/bot/info`，核對機器人身份與 HTTP 200。這不會推播，也不能驗證收件人可收到訊息。
- 檢查真實行情的股票、市場／幣別、交易日期、兩筆有效收盤價及計算結果。缺資料、配額或認證錯誤不能解讀成無跌幅；正式排程遇休市或未更新資料應跳過，手動歷史測試須標示交易日期。
- 未經本次推播授權，不執行 LINE 發送節點或可能連帶發送的完整流程。無股票符合門檻時如實回報，不偽造行情或自行降低門檻。獨立測試訊息也須先獲准。
- 範本手動執行不去重，重跑可能再次通知；正式執行依股票與交易日期去重。確認目標環境會持久保存正式通知紀錄，結果未知時不直接重送。HTTP 200只代表LINE接受，手機送達須由使用者確認。
- 使用者要求啟用後才 Publish，並讀回確認；存檔或手動成功不等於已啟用或已驗證自動排程。以 IANA 時區處理跨日與夏令時間。
- 秘密只存 n8n Credentials，不放一般 Variables、Code、聊天、匯出檔或暫存檔。呈現錯誤時遮蔽標頭、含 apikey 的 URL 與完整收件 ID；不自行購買額度、升級或繞過配額限制。

## 3. 最後集中引導憑證連接
全部結構與可預填設定完成後，再一次列出尚缺項目，指明節點、實際憑證入口、欄位與儲存步驟；已連接的不要求重做。這是 API Key／token 配置，不是 OAuth。

- **取得最近兩個交易日收盤價：Twelve Data Query Auth**
  - 使用者登入自己的 Twelve Data 帳號，把 API Key 私密輸入 n8n 憑證。
  - 憑證參數名稱設為 `apikey`，由憑證注入 query；Codex 綁定節點，不另寫一份 apikey 參數。
  - 可限制服務網域時設為 `api.twelvedata.com`。
- **LINE個人跌幅提醒：LINE Bearer Auth**
  - 使用者在自己的官方帳號／Messaging API Channel 取得 Channel access token，私密輸入 n8n token 欄，僅填 token 原文，不加 `Bearer` 前綴。
  - Codex 綁定節點；可限制服務網域時設為 `api.line.me`，不額外重複注入 Authorization 標頭。
  - 收件 User ID 由 Codex 確認後回填；此推播流程不需 Channel secret、Basic ID 或接收 webhook。
  - 尚無官方帳號／Channel 時，引導使用者完成官方建立與必要同意；秘密輸入及需本人操作的步驟交由使用者。

其餘節點不需額外帳號憑證。若工具無法安全配置秘密，開啟憑證介面讓使用者填入；不要改用聊天或一般 Variables 繞過。完成後 Codex 繼續綁定、回填與唯讀驗證，不把技術設定交回使用者。
